# 麦当劳 MCP 调用手册（MCP Calls）

- **Server**：`mcd-mcp` · `https://mcp.mcd.cn`
- **协议**：Streamable HTTP
- **鉴权**：`Authorization: Bearer <MCD_MCP_TOKEN>`
- **限流**：600 次/分钟（超限返回 `429`）

> ⚠️ 本文档只描述调用约定。工具入参/返回字段以麦当劳官方 MCP 实际返回为准，**任何情况下都不要凭猜测构造字段**。若字段名与本文不符，以实际返回为准并就地适配。

---

## 调用总表（整场冒险 4~6 次）

| # | Tool | 时机 | 调用次数 | 必要性 |
|---|---|---|---:|---|
| 1 | `now-time-info` | 序章 | 1 | 必选（判断早/正餐/夜宵时段） |
| 2 | `query-nearby-stores` | 序章 | 1 | 必选（定位场景） |
| 3 | `query-meals` | 序章末 | **1** | **必选，唯一一次** |
| 4 | `list-nutrition-foods` | 第三幕 | ≤1 | 可选（仅 careCalories） |
| 5 | `query-store-coupons` | BOSS | 1 | 必选 |
| 6 | `query-meal-detail` | BOSS 换品 | ≤2 | 可选 |
| 7 | `calculate-price` | BOSS 结算 | 1 | 必选 |
| 8 | `create-order` | 用户确认后 | 1 | 条件必选 |

**外送场景额外**：`delivery-query-addresses`（1 次）→ `delivery-query-stores`（1 次）

## 各工具要点

### `now-time-info`
- 用途：判断当前时段（早餐 10:30 前 / 正餐 / 夜宵），决定是否提示「现在是早餐时段，菜单不同」
- 返回：当前时间信息

### `query-nearby-stores`
- 入参：用户地址或经纬度
- 返回：门店列表（店名、地址、距离、营业状态、storeCode）
- **展示 3 家**，默认推荐「最近且营业中」的那家

### `query-meals` ★核心
- 入参：`storeCode`（+ 就餐方式，视官方字段而定）
- 返回：分类下的餐品列表（餐品编码、名称、价格、标签、售罄状态）
- **一次拿到后必须完整缓存**，后续所有过滤在本地完成
- 归一化要点：
  - 价格字段可能是分/元，需判断量级（>1000 视为分）
  - 售罄状态可能在 `status` / `soldOut` / `available` 字段，逐个兼容
  - 分类可能在 `category` / `categoryName` / 顶层分组的 key 上

### `query-meal-detail`
- 入参：餐品编码
- 用途：查套餐组成、可替换选项（「加 3 元换大份薯条」这类）
- 限制：每会话 **≤2 次**

### `query-store-coupons`
- 入参：当前门店
- 返回：可用优惠券列表（券 ID、门槛、优惠力度、有效期）

### `calculate-price`
- 入参：门店信息 + 就餐方式 + 商品列表（code + qty）+ 可选券 ID
- 返回：商品小计、配送费、优惠金额、应付总额
- **下单前必调**，用它的数字展示给用户，不要自己算

### `create-order`
- 入参：门店信息、就餐方式、商品列表、地址（外送）
- 返回：订单详情 + 支付链接
- **前置条件：用户已明确确认**
- 失败**不自动重试**（防重复下单）

### `cancel-order` / `query-order`
- 仅在下单后用户主动要求时调用

## 错误码处理

| code | 含义 | 处理 |
|---|---|---|
| 401 | Token 无效/过期/未提供 | 提示按 README 配置；提供演示模式 |
| 429 | 超过 600 次/分钟 | 退避 1 次（间隔 ≥2s），仍失败则走缓存/提示稍后 |

其他业务错误：读取 `message` 字段，用**用户能听懂的话**转述，不粘贴原始 JSON 堆栈。

## 演示模式（无 Token 时的兜底）

1. 读取 `assets/sample-menu.json`
2. 明确告知：**「当前使用 2026-10-xx 的快照菜单演示，不是实时数据，实际供应以门店为准」**
3. 全流程照常跑，但 `calculate-price` / `create-order` 用本地估算替代，并注明「演示模式不下单」

> 演示模式只用于体验流程，绝不冒充实况。
